# TaskBoard 仕様書

## 概要
Backlog風のプロジェクト・タスク管理WEBアプリケーション。

## 技術スタック
| レイヤー | 技術 |
|---------|------|
| フロントエンド | React + TypeScript + Vite + Tailwind CSS |
| バックエンド | Node.js + Express + TypeScript |
| データベース | PostgreSQL (Supabase) |
| ストレージ | Supabase Storage（アバター画像） |
| 認証 | JWT（jsonwebtoken） |
| デプロイ | フロントエンド: Vercel / バックエンド: Render（Webサービス、無料枠） |

## MVP スコープ

### 1. プロジェクト管理
- プロジェクトのCRUD（作成・一覧・更新・削除）
- プロジェクトキー（英大文字、例: `PROJ`）— 課題キーの接頭辞に使用
- プロジェクト名（必須、最大100文字）
- プロジェクト説明（任意、最大1000文字）

### 2. 課題管理
- 課題のCRUD（作成・一覧・詳細・更新・削除）
- 課題キー: `{プロジェクトキー}-{連番}` で自動採番（例: PROJ-1, PROJ-2）
- 件名（必須、最大200文字）
- 詳細（任意、テキスト、最大10000文字）

### 3. ステータス
| ID | 名称 | 色 |
|----|------|----|
| 1 | 未対応 | グレー |
| 2 | 処理中 | ブルー |
| 3 | 処理済み | オレンジ |
| 4 | 完了 | グリーン |

### 4. 優先度
| ID | 名称 | 色 |
|----|------|----|
| 1 | 高 | レッド |
| 2 | 中 | オレンジ |
| 3 | 低 | グレー |

### 5. 種別
| ID | 名称 |
|----|------|
| 1 | タスク |
| 2 | バグ |
| 3 | 要望 |
| 4 | その他 |

### 6. 担当者・登録者
- ユーザーマスタから選択
- 担当者: 任意（未割り当て可）
- 登録者: 課題作成時に自動設定（ログインユーザー）

### 6.5. アバター
- ユーザーはプロフィール画像をアップロード可能
- 対応形式: PNG, JPG, GIF（最大2MB）
- Supabase Storageの `avatars` バケットに保存
- 未設定時は名前のイニシャルをカラーサークルで表示

### 7. 期限日
- 開始日（任意）
- 期限日（任意）
- 期限日の前後関係バリデーション（開始日 ≤ 期限日）

### 8. 課題一覧・検索・フィルタ
- 一覧表示（レスポンシブ）:
  - **デスクトップ（md以上）**: テーブル形式（キー / 種別 / 件名 / ステータス / 優先度 / 担当者 / 期限日）
  - **モバイル（md未満）**: 1課題1カードのスタックレイアウト。ヘッダ行に種別アイコン・キー・ステータス、本文に件名（最大2行）、フッタに優先度・担当者・期限日
  - 種別はSVGアイコンで表現（タスク=チェックボックス、バグ=虫、要望=電球、その他=タグ）
  - 期限日が当日より過去かつ未完了なら赤色表示
- フィルタ条件:
  - ステータス（複数選択可、ボタントグル）
  - 優先度（複数選択可、ボタントグル）
  - 種別（単一選択、ドロップダウン）
  - 担当者（単一選択、ドロップダウン）
  - キーワード（件名の部分一致）
- ソート: 作成日（デフォルト）/ 更新日 / 優先度 / 期限日
- フィルタリセットボタン（フィルタ適用時に表示）

### 9. カンバンボード
- ステータス別の列表示（未対応 | 処理中 | 処理済み | 完了）
- 課題カードをドラッグ&ドロップでステータス変更
- カード表示内容: 課題キー、件名、優先度アイコン、担当者アバター

### 10. 完了理由
- ステータスを「完了」にした際に理由を記録する
- 完了以外のステータスでは空（NULL）

| ID | 名称 |
|----|------|
| 1 | 対応済み |
| 2 | 対応しない |
| 3 | 重複 |
| 4 | 再現しない |
| 5 | 仕様通り |

### 12. 親子課題
- 課題に親子関係を設定できる（最大2階層: 親→子）
- 親課題は同一プロジェクト内の課題のみ指定可能
- 子課題を持つ課題は他の課題の子にはなれない（孫課題は不可）
- 自分自身を親には設定できない
- 親課題が削除された場合、子課題の親参照はNULLに戻る
- 課題一覧ではツリー表示（親の下に子をインデント表示）
- 課題モーダルで親課題を選択可能

### 11. コメント
- 課題ごとにコメントを投稿・一覧表示
- コメント投稿者はログイン中のユーザー
- 新しいコメントが上に表示（降順）
- コメントの削除はコメント作成者のみ（UIからは自分のコメントの削除ボタンのみ表示）
- 本文中の `@ユーザー名` をハイライト表示し、メンション通知を発行する（13章参照）

### 13. 通知
- 課題ごと・ユーザーごとに通知を発行する。通知は最新50件まで保持（古いものはAPIで返さない）
- 通知タイプ:
  - **assigned**: 課題作成・更新時に担当者が変わった場合、その担当者本人へ通知（自分→自分のアサインは除外）
  - **mentioned**: コメント本文の `@ユーザー名` で言及された相手へ通知（自分→自分は除外）
- 既読/未読をフラグで管理。未読件数はサイドバーのベルアイコンと、モバイル時はハンバーガー上にもバッジ表示
- フロントは認証済みの間 1分間隔でポーリング取得（`NotificationProvider`）
- 通知をタップ／クリックで該当課題のURL（`/projects/:projectKey/issues/:issueKey`）へ遷移し、未読なら同時に既読化

### 14. メンション
- コメント入力欄（`MentionTextarea`）で `@` を入力するとユーザー候補をサジェスト
- 矢印キーで選択、Enter または Tab で確定。サジェストは部分一致で絞り込み
- サーバー側はコメント保存時に本文を走査し、`@ユーザー名` 部分一致でユーザーIDを抽出して通知を発行（名前の長い順に優先マッチ）
- 表示時はクライアント／サーバーで同じロジックを使い `@ユーザー名` をハイライト

### 15. URL ルーティング
- React Router を採用し、課題への直リンクを共有可能にする
- ルート構成:
  - `/login`, `/signup`: 未認証専用画面
  - `/`: 認証済みなら最初のプロジェクトへリダイレクト、プロジェクト0件なら作成導線
  - `/projects/:projectKey`: プロジェクト一覧
  - `/projects/:projectKey/issues/:issueKey`: 課題詳細
- リスト/ボード切替やフィルタ条件はURLに乗せない（state 管理）
- Vercel 側は SPA フォールバック（`vercel.json` の rewrite）で深いリンクの 404 を回避

### 16. レスポンシブ対応
- ブレークポイント: Tailwind の `md`（768px）。`md` 未満をモバイルレイアウトと扱う
- サイドバー: モバイルではドロワー化（オーバーレイ、画面外スライド）。ハンバーガーボタンで開閉。デスクトップは常時表示・collapse 可能
- 課題一覧: モバイルはカード型、デスクトップはテーブル（10章記載）
- カンバン: モバイルでも横スクロールで列表示。タッチデバイスでD&Dが動かないため、各カードに「移動」ボタン → ステータス選択シートでステータス変更
- 課題詳細: モバイルは縦積み（左カラム→属性パネル）でページ全体スクロール、デスクトップは2カラム独立スクロール
- 高さ計算は `dvh` を使用（iOS Safari のアドレスバー伸縮で余白が出ないように）

### 認証
| メソッド | パス | 説明 |
|---------|------|------|
| POST | /api/auth/login | ログイン（JWT発行） |

**認証方式**: JWT（Bearer トークン、`HS256` / 秘密鍵は `JWT_SECRET` 環境変数 / 有効期限7日）。`/api/auth` と `/api/health` 以外の全APIは認証必須。トークンはフロントエンドの `localStorage` に保存し、401レスポンス時に自動ログアウト＋リロード。パスワードは bcrypt（cost=10）でハッシュ化して保存・照合する。サインアップ時の最低長は8文字。

## デプロイ構成

### 構成
- **フロントエンド**: Vercel（Reactの静的ビルドをCDN配信）
- **バックエンド**: Render（Web Service、無料枠） — Expressをコンテナとして常駐
- **DB / Storage**: Supabase（PostgreSQL + Object Storage）

### フロント・バック分離について
- フロントとバックエンドは異なるホストにデプロイされるため、フロントの `VITE_API_BASE` 環境変数でバックエンドのURLを指定する
- バックエンド側ではCORS許可オリジンにフロントのドメインを追加する

### Render無料枠のスリープ対策
- Render無料Webサービスは15分アクセスが無いとスリープし、次回リクエストで30秒〜1分のコールドスタートが発生する
- **keepalive**: GAS（Google Apps Script）または UptimeRobot で `/api/health`（認証不要）を14分間隔で叩く
- 無料枠は 750時間/月のため、常時起動できるWebサービスは1つまで

### DB接続
- Supabase Transaction Pooler（port 6543）経由で接続する
- `pg.Pool` の `max` は 3 に固定

### サーバー設定
- Express body limit: 4MB（アバターBase64アップロード許容）
- CORS: `CORS_ORIGIN`（カンマ区切り）が指定されていればそのオリジンのみ許可、未指定なら全開（ローカル開発用フォールバック）
- 必須環境変数: `JWT_SECRET`, `DATABASE_URL`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`
- 起動時に `JWT_SECRET` が無ければプロセス終了
